### Bugs
Each was reproduced where it says so; the rest were traced through the code.
1. **A whitespace-only appendix name gives a 500** (reproduced). `portal/families.py:118` validates `NewAppendix`
   outside any handler, and the form's `required` accepts spaces (`portal/templates/family.html:41`).
2. **Resuming a run's events past the ledger's end never finishes.**
   - Reproduced: `GET /api/runs/{id}/events` with `Last-Event-ID: 999` on a finished run answers 200 with 0 events
     and no `done`.
   - A live job numbers every event, deltas included (`api/jobs.py:62`), but the ledger's replay numbers only what it
     holds (:147-150). So a browser that was watching when the process restarted reconnects with an id past the end.
   - It then reconnects forever: `frontend/src/lib/runs/events.ts:36-37` gives up only once the stream is CLOSED, and
     each attempt re-reads the whole run (`api/runs.py:257-319`).
3. **Re-scoring loses the run's events until restart.** `POST /runs/{run}/scores` replaces the run's Job
   (`api/scores.py:50`, `api/jobs.py:118-124`) with ids starting again at 1. `/events` prefers any in-memory Job, even
   a finished one (`api/runs.py:229-235`), though its description says the ledger answers when nothing is under way.
4. **`again` doesn't re-check the cases.** It checks only that the run is the person's own (`api/runs.py:194-203` →
   `bench/runs.py:43-51`); `start` checks every case's visibility (`api/runs.py:61-72`).
5. **`again` runs at the endpoint's current engine** (`bench/runs.py:73`), not the trial's. The ledger stays honest,
   since the new run has its own trial, but `docs/bench-api.md:746` says "the run's trial run again".
6. **A connection error looks like an event.** `events.ts:28-29` listens for `error` as one of the API's events and
   `JSON.parse`s it, so every reconnect throws a SyntaxError in the console.
7. **A refused run leaves the typed case stored.** The home island stores the text before it starts the run
   (`frontend/src/islands/Home.svelte:76`, then :79). A refusal (over quota, an endpoint down) leaves the text stored
   and counted against `TYPED_PER_DAY`, and each retry makes a new family. The endpoint list filters on
   `problem === null`, not on clearance (:48).
8. **The budget plugin crashes when no test runs** (reproduced: `--collect-only`): `quick / total` is a
   ZeroDivisionError at `test/budget.py:81`.
9. **`chatddx person password` accepts an empty password** (`cli.py:73-82`).

## 4. Before real patient data, or the public web
The portal is meant for the public web (`agents/wip-portal.md:288-292`) and stores what clinicians type. In order of
weight:
1. **Signing in can stall the app.** Each attempt runs argon2id (t=3, 64 MiB, p=4; 0.25–0.34 s here), and unknown
   logins pay the same. Both sign-in routes are synchronous and share anyio's 40-thread pool with every other
   synchronous route. With no limit on attempts, about 40 concurrent POSTs stall every page and read and hold about
   2.5 GiB (arithmetic, not measured). Every unauthenticated request also opens a Postgres connection before its token
   is checked (`api/people.py:55-58`, `portal/pages.py:68-81`).
2. **Database connections are unbounded and held.**
   - There is no pool (`api/state.py:21-33`).
   - Each run and each scoring holds its own thread and connection (`api/runs.py:79`, :144; `api/scores.py:48`, :56).
     The only cap is 100 runs a day per person, and the quotas read a count then insert, so a burst can overshoot
     them.
   - Each `/events` stream holds its connection for the whole run, since FastAPI 0.143 closes yield dependencies only
     after the response.

   One account can exhaust Postgres's default 100 connections.
3. **Memory and shutdown.** `Jobs` never evicts (`api/jobs.py:109-124`): every run's and scoring's events, judge
   calls included, stay for the life of the process. Run threads aren't daemons, and there is no lifespan hook, so a
   shutdown waits for runs, and a kill leaves them unfinished.
4. **Typed cases are kept for good.** `source.text` is insert-only (`store/migrations/0016-t2-source.sql:2-5`), with
   no route or command to erase a text or its family. Refused runs leave orphans (bug 7). Their fingerprints are
   unkeyed (`bench/cases.py:133`), as the run's are (`runner/rounds.py:153-162`).
5. **No security headers**: no CSP, frame-ancestors, nosniff, Referrer-Policy or HSTS. `/api/docs` and
   `/api/openapi.json` are public (`api/app.py:86-88`), and Swagger UI loads `swagger-ui-dist@5` from jsdelivr, with
   a floating major and no SRI, onto the session cookie's origin. With no inline script, `script-src 'self'` would
   fit every portal page.
6. **Rejected engine bodies are stored verbatim** (`runner/send.py:153-155`; only `prompt_token_ids` is stripped at
   `ledger/call.py:47`), and so is the engine's message in `Call.error`. Not verified against real vLLM.
7. **A digest works as a capability.** `GET /api/components/{digest}` has no visibility check (`api/world.py:76-86`).
   That is now design: appendices and expectations aren't sensitive (`docs/chatddx.md:17-19`). But the same holds in
   `Seen.variation(parts=…)` (`bench/seen.py:241-246`), so `/threads/{id}/variation` renders another person's unshared
   chunk text. `/threads/{id}/proposal` returns appendix text without no-store.
8. **Sessions.**
   - A password change leaves sessions open (`store/people.py:87-94`); no doc tracks this.
   - Nothing schedules `purge_sessions`.
   - `Role` is shown but never checked.
   - Signing in again leaves the earlier session open.
   - There's no command to deactivate someone, though `store/people.py:81-84` can.
   - Empty passwords are accepted (bug 9).
9. **Migrations are compared by name only** (`store/migrate.py:27-32`), and 08ae453 edits the applied
   `0002-t1-factor.sql` in place again (a no-op change). Freeze them before any shared database.
10. **Error text goes to clients.** `api/jobs.py:183-185` streams `f"{what} failed: {e}"` for any exception, and error
    pages show gate messages with an `OSError` in them (`runner/gate.py:42-43`).
11. **Writes are unlimited.** Appendices, threads, forks, edits, components and scorings have no count or size limit,
    and the app sets no limit on a request body.
12. **The engine client honours proxy settings.** `runner/wire.py:115` uses urllib's default opener, which follows
    `HTTP(S)_PROXY`, so vignette-bearing requests go through any proxy the environment names. Whether this matters
    depends on the deployment.

## Surprises
- **`pytest` doesn't run every test in a fresh checkout.** The 2 browser tests skip until `pnpm --dir frontend build`
  has run (`portal/test/test_browser.py:31`). Built, they pass.
- **This container is about 1.5× slower than AGENTS.md's timings**: 165 s against ~110 s, 32–36 s against ~22 s, and
  94 s against ~70 s with `-n 4`. The split holds: the quick run is 13% of test time.
- **The budget plugin's suggestions are mostly noise.** Of its 8 unmark suggestions, 5 are tests that use the
  `loaded` or `ran` templates, which AGENTS.md says stay slow; the plugin can't tell. Its 7 mark suggestions are all
  within 0.17 s of its line. Under `-n` its fixture accounting would be wrong.
- **The test World loads only under pytest.** `worlds/test/_data/factors.toml:36` and :48 pin
  `chatddx.runner.test.tools:*`, which only the root conftest registers (`src/chatddx/conftest.py:36-42`).
- **Each portal page parses the Vite manifest 2–3 times** (`portal/assets.py:47-51`).
