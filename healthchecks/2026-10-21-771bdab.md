### Bugs
Each was reproduced where it says so; the rest were traced through the code.
1. **A job whose connection fails stays "under way" until its worker restarts** (reproduced).
   - `_work` opens 2 connections (`worker/worker.py:189`). When that fails, or `queue.end` fails on a broken connection,
     the outer `except` only logs (:201-202), and `finally` drops the job from `_held`.
   - Liveness is the worker's `seen`, not the job's `beat` (`store/queue.py:29-34`), and the worker keeps beating, so
     the job is never claimable again. `j.beat` is written but never read.
   - Reproduced by capping the writer role at one connection more than at idle. A re-scoring got 202, then "too many
     connections for role"; with the cap lifted, the job was still under way 23 s later (the lost timeout is 10 s).
     Scoring again gets 409, and `/events` streams without ever sending `done`.
   - systemd's `Restart=on-failure` (`nix/module.nix:99`) doesn't help, since the process doesn't fail.
     `docs/modules/worker.md:36-37` says "A job whose work fails ends failed, with why".
   - Running out of connections triggers it, and bug 2 runs out of them.
2. **Scorings take connections with no limit** (reproduced).
   - A scoring job has 0 slots (`bench/runs.py:175-176`), so `j.slots <= f.free` always holds
     (`store/queue.py:309-315`), and the worker claims every queued one at once. Each takes a thread and 2 connections
     (`worker/worker.py:182-189`), and scoring has no quota.
   - Reproduced: 12 re-scorings posted together took the database's connections from 2 to 26. One account with 50
     finished runs reaches PostgreSQL's default 100.
3. **The NixOS module can't start the portal or a worker when `services.chatddx.facts` is set** (reproduced against
   the CLI; the VM wasn't booted). `nix/module.nix:29-32` and :96 append `--facts` to every service. `chatddx portal`
   and `chatddx worker` answer "unrecognized arguments: --facts". Only `init-data` takes it (`cli.py:494`).
   `agents/wip-error-handling.md:101-102` records it; wip-deploy doesn't.
4. **The README's walkthrough breaks twice.**
   - README:125 and :177 use `cell plan …`; the repl's `cell` was removed in #39 (reproduced). A piped repl exits 1 at
     the first unknown command, so the rest of the block doesn't run. `use plan` works.
   - The dev-db socket (traced). README:77 and `.env-devshell:2` put it at `$REPO_ROOT/dev-db/pgsock`. Since 8cd003b
     the shell sets `CHATDDX_STATE_HOME="$HOME/.local/state"` (`flake.nix:292`), and `dev-db` puts its socket under it
     (`scripts/dev-db.sh:1-2`), so `chatddx migrate` (README:91) looks for a socket that isn't there. `nix flake check`
     is consistent, since it sets `CHATDDX_STATE_HOME=$PWD` (`flake.nix:220`).
5. **The review page's score button re-scores everything once nothing is left.** `portal/review.py:242` passes
   `bench.unscored(started) or None`, and `None` picks every scorer that applies (`bench/runs.py:172`), judges
   included. A second tab or a stale page posting after the first scoring ended re-runs every judge call.
6. **A live `run.scored` holds only the scorers that job scored** (`worker/worker.py:226-227`,
   `api/telling.py:102-113`); a replay holds them all. The portal reloads on `done` and is unaffected; API clients see
   two shapes.
7. **Every surface's legend link is broken.** `docs/surfaces/*.md:3` links `[docs/surfaces.md](surfaces.md)`, which
   resolves inside `docs/surfaces/`. The source is `stamp/page.py:99-100`; refcheck skips the surfaces.
8. **The browser stage passes with nothing run.** `scripts/check.sh browser` exits 0 when all 12 tests skip for want of
   a browser (reproduced). `-rs` prints why, but nothing flags it.
9. **`stamp --check` passes with stamps pending**, by design (`agents/wip-stamp.md:36-39`). check.sh prints "N stamps
   pending" without `flag:`, and AGENTS.md:79 has agents relay only `flag:` lines, so a surface with an unstamped
   change can reach main silently.
10. **A malformed stamp is a bare `ValueError` traceback** out of `chatddx stamp` (`stamp/markers.py:56`, :60).

## 4. Before real patient data, or the public web
The previous list now lives in `agents/wip-clearance.md:162-269`, item by item, with a 13th, raw errors. The deploy
mitigates some items. In order of weight:
1. **Typed cases can reach real engines now.** See "Risky" above. There is no recorded decision to clear `typed`
   beyond the sample's fakes; `agents/wip-clearance.md:27-29` covers the sample's vignettes only.
2. **Database connections run out, and running out strands jobs.**
   - There is no pool (`api/state.py:22-23`), and the deploy sets no `max_connections` or PgBouncer
     (`nix/module.nix:336-355`).
   - Runs are bounded by an endpoint's capacity (`store/queue.py:302-317`), but scorings aren't (bug 2).
   - Each `/events` stream holds 2 connections (`api/runs.py:191-205`, `api/telling.py:168`); each app holds 1 for
     NOTIFY, and each worker 1 plus 2 per job.
   - When a job can't connect, it stays under way until a restart (bug 1).
   - The quotas still read a count, then insert (`bench/runs.py:207-218`).
3. **Sensitive text outside its places.**
   - `GET /api/runs/{run}` serves `call.failed` findings carrying the engine's own message, without no-store
     (reproduced: "HTTP 503: the engine is loading", no Cache-Control).
     `agents/wip-clearance.md:224` says such text is "served with a run's items only, which are no-store", and
     `docs/chatddx.md:53-54` counts an engine error that echoes a request as sensitive.
   - A worker failure's `why = str(e)` is kept and served (`worker/worker.py:195`, `api/runs.py:222-233`).
   - 500s answer `f"{type(e).__name__}: {e}"` (`api/app.py:60-62`).
   - Rejected engine bodies are stored verbatim (`runner/send.py:154`).
4. **NOTIFY carries model output to any role that can connect** (traced, latent). `item.delta`, `item.tool` and the
   judge's events go out by `pg_notify` on `run.<uuid>` (`store/notify.py:78-85`). Nothing revokes PUBLIC's CONNECT,
   so a `chatddx_reader` login that reads run ids from `catalog` can LISTEN and read model output it can't read in the
   ledger. Nothing uses the reader yet.
5. **Sign-in.**
   - argon2id still runs on synchronous routes that share the 40-thread pool, and every unauthenticated request opens a
     connection before its token is checked (`api/people.py:55-71`, `portal/pages.py:69-79`).
   - nginx limits the two sign-in POSTs to 10 a minute per address, with a burst of 5 (`nix/module.nix:362-368`), and
     the VM test checks the 429. Not covered: other unauthenticated routes, addresses rotated within a /64, the
     loopback port (`nix/module.nix:180-184`) and the Kubernetes target.
6. **Headers and public docs.**
   - The app sets no headers. nginx adds HSTS, nosniff, `Referrer-Policy` and `frame-ancestors 'none'`
     (`nix/module.nix:384-389`), with no `script-src`; the test checks HSTS only.
   - `/api/docs`, `/api/openapi.json` and `/docs/oauth2-redirect` answer without a session (reproduced). Swagger UI
     loads `swagger-ui-dist@5` from jsdelivr without SRI.
7. **Typed cases are kept for good.** `source.text` is insert-only, with no route or command to erase a text. The home
   page stores the text before it starts the run (`frontend/src/islands/Home.svelte:85`, :91), so a refusal or a
   failure leaves it. A job's `why` is kept for good too.
8. **Migrations.** They are known by name only (`store/migrate.py:27-32`), and 5e3b75a edited applied ones (§2). The
   deploy runs `chatddx-migrate` at every start, on a persistent database. The decided fix, checksums
   (`docs/backlog.md:434-441`), isn't built.
9. **Sessions.**
   - Fixed: expired sessions are purged at each sign-in, and the CLI refuses an empty password.
   - Open:
     - `set_password` neither ends sessions nor refuses `""` (`store/people.py:87-94`);
     - signing in again leaves the earlier session open;
     - `Role` is never checked;
     - there is no command to deactivate someone;
     - a deactivated person's queued jobs still run (`worker/worker.py:212`).
10. **Writes are unlimited.** Only `/scorers/try` (50 runs) and `/runs/compared` (20) have caps. The body limit is
    nginx's default 10 MB, not the 1 MB two plans state.
11. **Proxies.** The services unset all 6 proxy variables (`nix/module.nix:34-45`). The operator's `chatddx` wrapper
    doesn't (:102-126), so `repl` and `scripted-runs` run as root follow a proxy (`runner/wire.py:115`).
12. **Running it.** There is no egress control (the gate is the only barrier), no health route, and no CI.
