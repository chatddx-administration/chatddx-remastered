1. **Workflows.** Main's tip fails two of its own checks (F1). By what §1 pieces together, a hand edit went around the

3. **Actual problems.** Eleven, none of them in what is stored. F1 to F4 matter, F5 breaks the README's walkthrough,

### How a8228cc reached main

1. _Read_: at 01:05 UTC that day the agent's branch `claude/vigilant-archimedes-y9s63d` ends a turn at 594e984, which
   origin still has, with 5 stamps pending: one in `README.md`, one in `docs/comments/importers.md` and three in
   `docs/surfaces/`.
2. _Ran_, `git diff origin/claude/vigilant-archimedes-y9s63d a8228cc`: main's tip is that tree with the stamps
   resolved and four edits by hand. `TIKTOKEN_ENCODINGS_BASE` joins `_HOST_ENV` in `src/chatddx/importers/o11n.py`,
   the `# Policy:` comment above it goes, its test gets a line, and both hosts' `bind` changes in
   `worlds/kompismoln/endpoints.toml`.
3. _Ran_: the index wasn't written after the edit, so `docs/comments/importers.md:22-27` holds a comment the code no
   longer has. `chatddx-dev index` writes it as one stamp pending.
4. _Inferred_: the commit didn't come out of `./dev/operator.sh merge`. Its author and committer dates are 53 minutes
   apart, and merge's squash is a commit of its own (`dev/operator.sh:90`). `stamp` refuses this tree on `index`
   (`dev/operator.sh:48`), and `merge` on `python-tests` (`dev/operator.sh:80`).

Nothing in the app is the worse for it: an index of comments is stale. What it shows is that the workflow assumes a
change ends in an agent's turn, where `turn-end` writes what follows from the code. A human's edit has no such step.
`operator.sh stamp` checks and writes nothing, so the way on is `./dev/write.sh index`, resolve, stamp again; or around.

**F2. CI runs nowhere this session can see, and the docs disagree on whether it runs.** _Ran_: GitHub's API lists no

**F3. CI's command has failed since the day it was written.** _Ran_: `nix build .#checks.x86_64-linux.package` at

the `diagnoses` configuration it fits. The backlog has the cause as "A view's reach knows the type it picks"
(`docs/backlog.md:130`), without what it does to a score. Fix: the backlog's, that such a view isn't offered.
